# ADR-002: Remove the daily planner; no scheduled pass; stories on demand

## Status

Accepted (user direction, 2026-10-19)

## Date

2026-10-19

## Context

The 18:00 planner (`trec plan`, LaunchAgent `local.teams-recorder.planner`) re-reads the day's analyses, the previous plan and the open-actions list, writes `plans/<day>.md/.json`, updates `open_actions.json`, and drafts user stories automatically. It is where tasks are born, closed and marked overdue, which caused the visibility gaps in the Motivating Problem. The user asked to remove the analysis from the 18:00 flow and said not every meeting activity is a task or a story.

## Decision

Remove the planner entirely: use case, port, adapter, prompt, plan files as inputs, open-actions list, `trec plan`, the scheduled job, and automatic story drafting. Do not replace it with any scheduled pass (morning or evening): the box writes absolute dates next to its update time, so a box from yesterday is still correct. Audio retention, which ran as `trec plan --purge`, moves to the daemon: the first tick of each day schedules it in the background (the detector tick never runs it inline). Stories are drafted only for items the user tags `#história`, via `trec stories`. The curator runs alongside the planner in a shadow period before the removal; the removal ships when the user says go.

## Alternatives Considered

### Alternative 1: Keep the planner for narrative only

- **Description**: one daily call writes priorities citing items; no state changes.
- **Pros**: a daily written synthesis.
- **Cons**: a second document, a daily model pass re-reading model output, a second place to look.
- **Why rejected**: the user asked to remove it.

### Alternative 2: Morning refresh pass

- **Description**: a scheduled meeting-less pass updates focus and housekeeping before the workday.
- **Pros**: the focus reflects the new day.
- **Cons**: the planner reborn under another name; scheduling code and config.
- **Why rejected**: critic round 2; absolute dates make it unnecessary.

## Consequences

### Positive

- One document; nothing runs at 18:00; fewer model calls per day.
- Stories become intentional.

### Negative

- No daily prose synthesis.
- Before the first meeting of a day the focus reflects the previous day's last pass (dated).

### Risks

- An old planner job still installed would run `trec plan --purge` at 18:00 and fail with exit 2 every weekday — mitigated: `agent install`, `agent restart` (the step already required after a code change), `agent uninstall`, and the installer and uninstall scripts remove it. Its label and task name survive only as `constants.Legacy` identifiers, used to build a `LaunchAgent`/`ScheduledTask` whose only call is `uninstall()`.
- Scripts reading plan files (`fidelity_eval.py`, `wiki_corpus.py`) — updated in the same change.

## Implementation Notes

Internal code is hard-cut (no shim), except the legacy identifiers needed to remove the installed job. `PurgeOldAudio` moves to `use_cases/retention.py` with its default from `constants.Audio.RETENTION_DAYS`. `data/plans/*` stays on disk unread; story drafts keep living in `plans/<day>.stories.*`. `[planner] retention_days` is read as a fallback for `[audio] retention_days` for one release; `[stories] enabled` is ignored.
