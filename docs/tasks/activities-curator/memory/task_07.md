Decisions for later tasks:
- `ActivitiesStatus` / `ActivitiesSummary(repo, store, curate, fmt=doc_format())` in `use_cases/activities.py`; `Container.activities_summary()` builds it (task_10 reuses it for `doctor`/`status`). `last_pass` is the last `meeting` or `undo` record, and `updated`/`titles` come from it (a failed or skipped pass is not an update); `not_curated` is in use-case order (oldest first), `trec activities` prints it newest first (the `_dx.md` golden). With no document the status carries `exists=False` and still lists `not_curated`; the CLI prints only the bootstrap hint then.
- New pure domain readers (exported from `teams_recorder.domain`): `box_focus(fmt, document)` (the numbered `> N. ` lines of the box as stored, without `> `) and `section_counts(fmt, document)` (per heading: open checkboxes under actions/waiting, unindented non-blank lines under agenda/context; a section ends at the next `## ` line; renamed/removed heading absent; a user `##` section is never counted).
- `passes_by_day(days: {id: date})`: chronological, never two days in a pass, `Activities.BATCH_SIZE` per pass. `trec activities curate` (ids and `--since`) uses it; `trec analyze` uses `batches(analyzed_ids)` (oldest first, mixed days allowed), as `_spec.md` says. `--since` takes every analyzed meeting with `day >= since`, curated ones included (reruns are safe).
- `cli._curate_passes(c, passes) -> failures` prints one line per pass for the meetings it curated (`Curating <title> (<dd/mm>), … ok (<edits> edits) — <summary>`, titles joined by `, `) and one `Curating <title> (<dd/mm>)… failed: <reason>` per meeting that failed alone; `waiting for the curator…` is printed by `on_wait` before the pass line (the line is printed after the pass, not before, so the golden order holds). A `TeamsRecorderError` out of `execute` (lock/document unreachable) fails every meeting of that pass. Edits are not pluralised (`1 edits`), like `ANALYZED_OK`.
- Confirmation: `Curate N meetings in P passes <via> (~M min)? [y/N]: ` with `typer.confirm(default=False)`; `M` = P x `Activities.EST_SECONDS_PER_PASS` (160 s) rounded UP to a multiple of `Activities.ESTIMATE_STEP_MINUTES` (5), which reproduces the `_dx.md` example (9 passes -> ~25 min, 24.0 exact); `Cli.CURATE_VIA` is keyed by the provider value. `n` -> `Nothing curated.`, exit 0. No analyzed meeting since the date -> `No analyzed meeting since <date>.`, exit 0, no prompt. Ids and `--since` together, or neither -> `error: ...`, exit 1.
- `curate <id>`: unknown id uses the existing `Cli.MEETING_MISSING` (`error: meeting <id> does not exist`; the `_dx.md` "Meeting not found" wording does not exist in the code base); a meeting not analyzed prints `Meeting <id> is <state>, not analyzed: run trec analyze <id> first.` (no `error:` prefix, stderr) and exits 1, where state is `derive_status(files - {ERROR})` (a meeting whose analysis failed is `transcribed`). Validation of ids comes before the LLM prerequisites check; prerequisites before the confirmation.
- `trec analyze`: after the loop, `if analyzed and settings.activities_enabled: _curate_passes(c, batches(analyzed))`; the exit code only reflects analysis failures. `trec activities curate` ignores `[activities] enabled`.
- `--open`: `cli._open_document(path, *, platform=sys.platform, startfile=None, run=subprocess.run)` (`open` via `Bin.OPEN` on macOS, `os.startfile` looked up with `getattr(os, Cli.STARTFILE)` on Windows); tests patch `cli._open_document` and call it directly with fakes. Never run for a missing document; an `OSError`/`SubprocessError` prints `error: could not open ...`, exit 1. Windows path not run on real Windows.
- The sub-app is `activities_app` (`invoke_without_command=True`, the `--open` option on its callback) in `cli.py`; task_09 adds `undo` with `@activities_app.command("undo")`.
- Messages: `Cli.ACTIVITIES_*`, `Cli.CURATE_*`, `Cli.CURATING*`, `Cli.CURATED_*`, `Cli.CURATION_FAILED`, `Cli.WEEKDAYS_SHORT`, `Cli.WHEN`; constants `Activities.EST_SECONDS_PER_PASS`, `Activities.ESTIMATE_STEP_MINUTES`, `Bin.OPEN`.
