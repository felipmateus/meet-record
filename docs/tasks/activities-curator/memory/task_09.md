Decisions:
- `UndoLastPass(store, clock, fmt=doc_format())`. Target = last `PassKind.MEETING` record whose version no `UNDO` record names in `undoes` (so failed/skipped/undo records are skipped and undone passes are walked past). `execute(expected_version)` inside `lock(wait=False)`: busy -> `CuratorBusy(Err.CURATOR_BUSY)`; no target -> `NothingToUndo(Err.NOTHING_TO_UNDO)`; target != expected -> `UndoStale(Err.UNDO_STALE)` (also when another undo ran meanwhile); then `commit(current or "", N.before, [], N.prevbase, undo_record)` and `truncate_archive(N)` inside the same lock.
- Undo record: `kind=UNDO`, `meetings=N.meetings`, `during_edits=N.carried_edits`, `carried_edits=""`, `undoes=N.version`, `summary=""`, `doc_chars=len(restored)`, its own version from `free_version(store, clock.now())` (CurateMeetings._version delegates to it).
- Spec deviation: `UndoPreview` is `(version, record, diff, edited_after)`, no `archive_stays`: the store port cannot report an archive size before the commit; the post-fact flag is `UndoResult.archive_left_in_place`. `UndoResult.version` is the undone pass's version. `diff` = `unified_diff(body(now), body(N.before))` (hunks only; the CLI prints `--- now` / `+++ before the pass` itself); `edited_after` = max(added, removed) lines of `unified_diff(body(N.after), body(now))`.
- CLI: preview is always printed (also with `--yes`, which skips only the confirmation); decline prints `Nothing restored.`, exit 0; busy / nothing / stale print the `_dx.md` text plain on stderr (no `error:` prefix), exit 1; any other `TeamsRecorderError` (e.g. version files rotated away) uses `_fail` (`error: ...`). Restored line names every meeting id of the pass (`that meeting` / `those meetings`). Undo builds no curator and needs no LLM prerequisite.
- Known edge, left as ADR-003 accepts: an undo killed after `base.md` was changed but before the pass-log line, whose restored text has no stamp, rolls back with `base.md` already switched to the old base (reconcile does not restore base.md); a retried `undo` is idempotent. The tests stop the undo before the base step, which is the case the ADR and UT-126 describe.
- The priming/first `meeting` record is undoable like any other; after undoing every pass of a test the preview shows the primer.
