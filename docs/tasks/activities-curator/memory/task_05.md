Decisions for later tasks:
- Spec gap closed: `ActivityStore.log_pass(record)` (port, `FsActivityStore`, `InMemoryActivityStore` with `fail_log`/`logged`) appends a record to the pass log with no version files, no document or base write. A `skipped_empty` or `failed` pass uses it (UT-032 "document unchanged", UT-034 "nothing committed", IT-004 "version files not written"); only a pass that changes the document uses `commit`. Such records have no version set: task_09's `UndoLastPass` must pick the last `meeting` record (skip `undo`, `failed`, `skipped_empty`) and `store.version(...)` only for those.
- `CurateMeetings.execute(ids)` takes the 4 oldest of `ids` (`next_batch`, each id once, sorted: ids sort by start time) and ignores the rest. Callers batch with `batches(ids)` (module functions in `use_cases/activities.py`): the daemon worker (task_06) and `trec analyze` / `curate --since` (task_07) loop over `batches(...)` themselves; the CLI estimate is `len(batches(...))` passes.
- `execute` busy and `wait=False` raises `CuratorBusy(Err.CURATOR_BUSY)`; busy and `wait=True` calls `on_wait()` once, then blocks. Everything else never raises out of a failed pass (a failure is in `PassResult.failed`, an `Exception` in a pass is converted, a `BaseException` such as a hard stop propagates).
- `PassResult.failed` reasons are bare (`Claude Code timed out after 900 s`); `curation_error.txt` is `Err.CURATION_FAILED` (`Activity curation failed: <reason>`, the `_dx.md` Errors table); `NotCurated.reason` is the file text as stored, so task_07's `Not curated:` listing prints it as is or strips the prefix to match the `_dx.md` golden output (`Err.CURATION_FAILED.format(reason="")` gives the prefix).
- `CurateMeetings` has one field beyond the spec: `fmt: DocFormat = doc_format()`. New public helpers in the module: `skeleton(fmt)`, `batches`, `next_batch`, `has_content`, `refs_of(n, analysis)`.
- Skeleton: title, box (closing marker `skeleton_stamp`), the four headings each followed by one blank line, empty link block. No blank line sits right under a heading, so `insert_after <heading>` gives a continuous list; a section the model wrote with a blank line under its heading still splits (task_04 note; prompt measure Q-002).
- A pass reads the document once as `F` (skeleton when there is none, and then the base is ignored: `user_edits` is "" and `carried_edits` ""), calls the curator, re-reads `F'` (`F` when the file vanished), applies, repairs once, and commits `commit(F', written, archived, base', record)`: `before` is `F'`, `written = render_links(rescue_box_lines(base'))` (so rescued lines bring their link definitions), `base' = render_links(render_box(W))`. `box_rescued` counts typed box lines not already in the body of `base'`. `retried_by_kind` is keyed by the failed op's kind (`replace`, ...). `unaccounted_refs` = refs shown (`refs_of`, numbered over the meetings the curator saw) minus op refs (both rounds) and ignored refs.
- A mixed batch (some meetings with nothing extracted) calls the curator for the others only; the pass record lists every id of the batch, so `pending()` sees the empty ones as curated. A batch of only empty meetings logs one `skipped_empty` record.
- A pass's version is its time (`Activities.VERSION_FORMAT`) moved on by whole seconds while any record in the pass log already carries it (failed and skipped records too).
- `pending()` / `not_curated()` use `repo.meeting_ids()` + `files()` (ANALYZED) + `load_meta` (a damaged meta is logged and skipped), the window `Meeting.day >= working_days_ago(today, n)`; an undo record does not make an undone pass "not curated" (only `meeting` and `skipped_empty` records are successes), so an undo never re-queues the meeting; the user re-runs `curate <id>`.
- Known edge, not handled: if `commit` raises after the document replace (`RepositoryError` `ACTIVITY_COMMIT_INCOMPLETE`), the pass counts as failed and a failed batch is then re-run one meeting at a time within the same lock hold, against a stale `base.md`; the next `lock()` completes the first pass. Rare (three retries of base/log write failed); follow-up if it ever shows.
- `domain.clock_seconds(at)` (HH:MM:SS to seconds) is new in `domain/excerpts.py`; `verifier_claude._seconds` is the same code and could use it.
