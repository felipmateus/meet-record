# Issue 009: IT-002 cannot pass as written: one stereo file, -120 at tone edges

## Review Comment

Runtime check with ffmpeg 9.0.1, running the documented chain (`-af aresample=16000,asetnsamples=n=1600,astats=metadata=1:reset=1,ametadata=mode=print:key=lavfi.astats.Overall.RMS_level:file=-`, then `-f null -`).

**Output shape.** Output goes to stdout with exit 0, and stderr is empty with `-loglevel error`. Each 100 ms frame prints two lines:
- `frame:15   pts:24000   pts_time:1.5`
- `lavfi.astats.Overall.RMS_level=-85.545672`

Silence prints `-inf`, and `pts_time` is printed as `0`, `1`, `2` with no decimals. UT-074's sample matches this shape.

**One stereo file cannot work.** IT-002 measures "a generated 3 s stereo WAV" with tap and mic as tracks. `EnergyMeter.measure(track)` measures one file, and `Overall.RMS` spans all channels. A stereo WAV with L = tone 0–1.5 s and R = tone 1.5–3 s gives a flat −24.08/−24.13 dB on all 30 frames, so the two timelines never appear.

**The edge frames are not −120.** With two files (tap.wav stereo with a tone over 0–1.5 s; mic.wav mono with a tone over 1.5–3 s):
- tap: frames 0–14 read −21.07, frame 15 reads **−85.55**, frames 16–29 read `-inf`;
- mic: frames 0–13 read `-inf`, frame 14 reads **−101.52**, frames 15–29 read −21.12.

The resampler leaves a finite level in the window next to each edge, so "−120.0 elsewhere" fails on one frame per track. A 3.05 s tone gives 31 frames, the last one zero-padded (−24.08 instead of −21.07).

**Speed is fine.** One hour of stereo audio (generated by `anoisesrc` and piped, no file) took 9.5 s and printed 72,000 lines. That matches ADR-002's "seconds for an hour".

Suggested fix: generate two files. Assert levels above −30 inside the tones and at or below −80 elsewhere, or exactly −120 excluding the frame next to each edge. Pick segments away from the edge, for example [0, 1.4] and [1.6, 3.0]. Document the zero-padded last window.
