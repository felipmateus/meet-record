# ADR-001: Whole-audio VAD with whisper.cpp's tool before transcription

## Status

Proposed

## Date

2026-10-22

## Context

Recordings with nobody speaking go through whisper, which invents text for them. With language detection, whisper can also label them English (language-detection G1, two recordings).

The user decided on 2026-10-22:

- a recording with no speech is not transcribed;
- its transcript is saved empty;
- a warning is logged, and a recording of 1 minute or more notifies;
- the flow continues;
- language samples without speech must not vote.

The project already ships Silero VAD (`ggml-silero-v5.1.2.bin`) for the anti-loop retry, and Homebrew's `whisper-cpp` 1.9.4 installs `whisper-vad-speech-segments` next to `whisper-cli`. Measured on all 28 stored recordings:

- the two no-speech recordings → 0.0 s of speech;
- every other recording → 7.3 s or more;
- VAD time → 19 s for 86 minutes of audio.

## Decision

Before the language detection and before whisper, run Silero VAD once over the whole recording with `whisper-vad-speech-segments`. Use the project's VAD arguments and convert the audio to a 16 kHz WAV with ffmpeg first. The pure result serves three purposes:

1. under 2.0 s of speech → no speech, and whisper is skipped;
2. the speech inside each planned language sample → samples with under 3.0 s are not sent;
3. the WAV's length → stands in for a missing meeting duration.

The check is advisory: any failure means today's behavior.

## Alternatives Considered

### Alternative 1: VAD on whisper's first pass (`[transcription] vad = true` by default)

- **Description**: Turn on whisper-cli's own `--vad` for every transcription. Whisper then skips silence, and an all-silence file yields no segments.
- **Pros**: No new tool or process, and no extra conversion.
- **Cons**:
  - It changes the transcription of every meeting with speech, which goes against the requirement that recordings with speech are transcribed exactly as today. Portuguese meetings have run with VAD off on the first pass since the start; the retry is the only pass that uses it.
  - It gives no measurement before the language detection, so silence still votes.
  - "No segments" cannot be told apart from a whisper failure that wrote an empty JSON.
  - There is no number to show the user.
- **Why rejected**: It changes healthy meetings and still does not serve the language vote.

### Alternative 2: An ffmpeg loudness threshold (`volumedetect` / `silencedetect`)

- **Description**: Call a recording silent when its mean level is under a threshold, such as -50 dB.
- **Pros**: Only ffmpeg, which is already required. Fast.
- **Cons**: Noise is not silence. The 5-minute no-speech recording is noise at an audible level and would pass as "speech". A quiet but real meeting could fail it.
- **Why rejected**: It cannot tell a voice from noise, which is the case that matters.

### Alternative 3: VAD only inside the language detector, per 30-second clip

- **Description**: Run VAD on each language clip and drop the clips without speech.
- **Pros**: It is contained in one adapter.
- **Cons**:
  - Whisper still transcribes empty recordings and invents text, so the Motivating Problem is not solved.
  - Nothing is detected with `language` fixed.
  - It runs up to 12 VAD processes instead of one.
- **Why rejected**: It solves only the smaller half of the problem.

## Consequences

### Positive

- One measurement serves the verdict, the language samples and the duration.
- Recordings with speech get the same whisper commands as with the check off, for the language they are given: byte for byte with a fixed language. In auto mode only the `-l` value can change, through the language-sample filter, the planned-count rule and the duration stand-in.
- The tool comes from the same package as `whisper-cli`, and the model is the one already downloaded for the retry.

### Negative

- One more ffmpeg conversion and one VAD run per meeting: about 20 s on an 86-minute meeting, against about 12 minutes of whisper.
- One more external tool to find (`find_tool`), to report in `trec doctor`, and to keep parsing across whisper.cpp updates.

### Risks

- **A false "no speech".** Mitigated by:
  - the threshold far below the smallest real recording (2.0 s against 7.3 s);
  - the notification;
  - the 30-day audio retention;
  - the recovery: `speech_check = false`, `trec transcribe <id>` and `trec analyze <id>`, then the check back on (`_spec.md` › Business Rules).
- **An output format change.** The parser requires the count line to match the segment lines, so a change reads as a failed check, never as "no speech". The opt-in real test catches it.
- **Windows archives without the tool.** The check is skipped with a warning, and `trec doctor` reports it.

## Implementation Notes

- The tool prints `Detected <n> speech segments:` and then `Speech segment <i>: start = <cs>, end = <cs>`, in centiseconds. This was verified on 2026-10-22: a 27.3 s file's last segment ends at `2067.00`.
- `-np` keeps only the results and the ggml/Metal start-up lines, which the parser ignores.
- The audio length is read from the WAV header, not from the tool's output.
